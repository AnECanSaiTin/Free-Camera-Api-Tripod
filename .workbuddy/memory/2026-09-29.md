## 第 2 步改造：变量表 / 函数表抽成 SymbolTable（已实施，编译通过）

承接 9-28 的路线（第 1 步 eval 求值层已落地提交）。本次把散在 `CameraAnimation` 里的两张表和
引用完整性整段搬走，`CameraAnimation` 685 行 → 约 480 行（净减 180 行）。

新增 `api/animation/expression/`：
- `SymbolTablec`：只读视图（沿用项目 `XXXc` 命名惯例）。查询项：variables / variable(name) /
  functions / function(name) / functionNameTaken / cycle
- `SymbolTable implements SymbolTablec`：两张 `ArrayList` + 全部增删改名，外加三段 responsibilities
  - 名字唯一性：`addVariable()` / `addFunction()` 自带 `var{n}` / `f{n}` 自动命名（常量
    `VARIABLE_NAME_PREFIX` / `FUNCTION_NAME_PREFIX`，上限 1000）
  - 引用完整性：`rebindTrack(old,new)`（轨道改名改指向）、`unbindTrack(id)`（轨道删除转固定值 0）、
    `replaceFrom(SymbolTablec)`（copyFrom 用的整体替换，装副本）
  - 静态扫描：静态 `references(Keyframec, String)` / `references(ValueSource, String)`

分工要点：**SymbolTable 不认轨道也不认曲线**。它只提供扫描单个键是否引用某名字的静态方法，
"取出变量绑定的那条曲线并遍历每个键"这一步留在 `CameraAnimation#selfReferencing`（那里才有轨道表）。
这样 expression 包不用依赖 curve / eval，包依赖方向没破坏。

对外 API 变化：`CameraAnimationc` 的 `variables()` / `functions()` 合并为
`SymbolTablec symbols()`；`CameraAnimation#symbols()` 协变返回可写的 `SymbolTable`。
调用点全部改用 `symbols()`：ExpressionScope.of、AnimationCodec（读两端）、ExpressionEditorWindow、
VariablePanel、FunctionPanel。顺手**收敛了两处重复的变量自动命名 for 循环**（两个面板各一份）。

行为有意保持不变的地方：`addVariable` / `renameVariable` 仍然**不拦**内置变量名（`t`/`p`/`wt`），
只在 UI 改名那一步拦——怕改了会让旧存档里同名的变量读不进来。

## 环境踩坑（下次直接照做）

1. **Bash 工具缺 coreutils**：`ls` / `head` / `grep` / `uname` / `xargs` 全部 not found，
   `./gradlew` 直接跑不起来。改用 PowerShell；文件搜索一律走 Glob / Grep 工具。
2. **PowerShell 工具拿不到 stdout**：命令的回显不会返回，必须重定向到文件再 Read。
   且临时文件建议放 `.workbuddy/` 或直接删（`Remove-Item` 有时第一次会失败，重试一次就好）。
3. **编译命令**（必须显式给 JDK 25，系统默认 JAVA_HOME 是 JDK 21，构建要求 toolchain 25）：
   `Set-Location D:\Code\Java\FreeCameraAPIAddition; $env:JAVA_HOME="D:\Code\Java\Jdk\Oracle25";
   & .\gradlew.bat compileJava --offline 2>&1 | Out-File compile-out.txt -Encoding utf8`
   本机的 JDK 都装在 `D:\Code\Java\Jdk\`（17 / 21 / Oracle25 / Oracle26）。
4. **Edit 同文件并发会互相覆盖**：一次消息里对同一个文件发多条 Edit，后面的基于旧内容写入，
   会把前面的改动抹掉（工具仍报 success）。**同一文件的编辑必须一条一条串行，改完 grep 复查一遍。**

## 第 3 步：Clip 与 tracks 合并（曲线只存一份，已提交 cb6db01）

`curve/Clip` 是与轨道表平行的第二份曲线容器，增删改名要维护两处，**已整个删掉**：
- 曲线唯一归属 `CurveTrack`；按名取曲线的入口是 `CameraAnimationc#curve(id)`
  （实现：`tracks.get(id) instanceof CurveTrack`），播放器与求值层都走它
- `CameraAnimation.duration()` 不再有 `clip.duration()` 这一项（曲线轨道本就在轨道表里，循环已覆盖）
- `CurveSampler.sample(Clip, ...)` → `sample(CameraAnimationc, ...)`；缺通道时该组取 NaN（以前会 NPE）
- `ExpressionScope` 的 `findCurve`（每次线性扫 `curveTracks()`，而该方法每次还 `List.copyOf`）
  与它那层 `curveCache` 一并删掉，改成 `animation::curve` 直接查表——顺带修掉 9-28 记录里的热路径第 8 条
- `Clip` 的 `name` / 手动 `duration` / `addKey` / `removeKey` 从来没人调用，随类一起删

## 第 4 步：值源分型 + Scope 拆分（已提交 71d99f2）

值源：`ValueSource.withConstant(v)` 与 `copy()` 由静态 switch 改成**实例方法**，
三种来源各自实现（固定值改自己 / 公式改回退值 / 轨道读数换成新的固定值源）。
以后加第四种来源时只动它自己那一个类，不用回来补 switch。

Scope：`Scope` **不再 extends `Expression.Resolver`**，现在只有环境量（time/p/wt）+ 轨道读数 `track(id)`，
另加 `Expression.Resolver resolver()`。名字解析与函数查询回归 `Resolver`。
`ExpressionScope` 同时实现两个接口、`resolver()` 返回 this——解析变量要读轨道、读轨道又需要时间，
两者在这一个实现里天然合一，但对**用**它的人是分开的两件事。
受影响的调用点：`FormulaValue.evaluate`（`scope.resolver()`）、
`ExpressionEditorWindow.previewResolver`（预览用的包装器改成包 `resolver()）、`Scope.evaluate(String)` 默认实现。

Scope 接口片段、包结构树）。
