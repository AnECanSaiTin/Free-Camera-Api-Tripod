## 历史资料与维护规则

[重构前勘察](<_survey-current-code.md>)描述旧根包的历史状态；[功能对照评审](<review-feature-parity.md>)保存产品取舍与修订，不作为当前实现清单。旧批次的完整记录由 Git 历史追溯；不把历史“未提交/待实现”恢复为当前状态。

行为变化同步主设计；UI/音频边界同步各自设计；施工状态只在实施文档维护；审核编号与证据只在审核文档维护。对“未实施”“已实现待验”“原反例关闭”“新发现待修”“设计建议待定”明确区分。临时探针在 build 下，可能被 clean 清理，审核正文必须包含可重建的输入和输出证据，不仅链接临时文件。
