# 相机动画编辑：市面常用功能对照与可实现性评估

> 本文 §1–§8 保留最初对照与建议，不能将其中“已覆盖/能做/成本小”视为已实现或已验证。现已完成二次评审并合并设计，**采纳状态、技术纠正与本次用户确认以 §9 为准**；规范以两份设计文档为准。

对照对象：[动画、播放与编辑器重构设计](<design-animation-editor-framework.md>)（下称"主设计"）与
[编辑器 UI 框架重构设计](<design-editor-ui-framework.md>)（下称"UI 设计"）。
参照软件见 §7；MC 同类 mod 的特性取自其官方 README（[Aperture](https://github.com/mchorse/aperture)、
[Blockbuster](https://github.com/tomsoel/blockbuster)），其余为通用功能。

## 1. 结论摘要

| 维度 | 判断 |
| --- | --- |
| **单镜头运镜本身** | **达到主流水平，个别处更强**：关键帧/曲线/路径/FOV/Roll/局部空间/事件轨道都在设计内；"值可以是公式"这一点比多数 MC 相机 mod 强（对标 AE 表达式、Houdini） |
| **与 DCC / 引擎的差距** | 集中在四类：**剪辑（多镜头/过渡）、渲染后期（景深/运动模糊/色彩）、模拟类（物理/IK/世界状态驱动）、互导** |
| **受 MC 渲染层限制做不到的** | 景深、运动模糊、快门、镜头光晕、色彩分级等后期效果——不是设计取舍，是宿主能力边界 |
| **本轮确认不做** | 出片导出、镜头过渡（未来视发展而定）、外部格式互导、反向播放、多重镜头工程 |
| **本轮确认要做、主设计尚未收录** | 注视目标（look-at）、锚点位置进入表达式、参考音轨与播放同步、相机避障开关、**多机位同时渲染与画面合成**、**声明式世界采样** |
| **其中改动最大的一项** | **多机位同时渲染**：它把"一份文档一套相机通道"改成"一份文档若干机位"，主设计的 §3.1 / §6.3 / §6.4 / §7.1 / §7.2 / §8.1 / §9.1 都要跟着扩，见 §5.5 |
| **建议补的缺口** | 标记/注释、工作区循环区间、确定性噪声函数、洋葱皮、构图辅助、轨道显隐独奏、缓动预设、烘焙、批量数值运算、自动保存（§6） |

一句话：**"拍一段镜头"这件事能做到与市面同水平；"剪一场戏、出一支片"整类不做；
"渲染质感"受 MC 限制做不到。** 本轮新增的四项（注视、锚点读数、音轨、避障）
恰好补上了 MC 同类 mod 最有辨识度的几个卖点。

## 2. 判定口径

| 标记 | 含义 |
| --- | --- |
| ✅ | 主设计/UI 设计已覆盖，按设计实现即可得到与市面软件相同的效果 |
| ➕ | **本轮新确认要做**，主设计尚未收录；§5 给出设计要点与影响（§5.5 的多机位同时渲染会改动数据模型） |
| 🟨 | 机制上允许（多数是工具层或扩展轨道），但文档没写，需要补一条设计决定 |
| ❌ | 本轮明确不做，或受 MC 渲染层限制做不到（附原因） |

判定依据一律指向文档章节；`§` 指主设计，`UI §` 指 UI 设计。

## 4. 综合判断：效果能不能做到

| 能力维度 | 结论 |
| --- | --- |
| 单镜头运镜（关键帧 + 曲线 + 路径 + FOV/Roll + 局部空间） | **能，与主流同水平**；公式化关键帧比同类 MC mod 更强 |
| 程序化镜头（表达式、变量、函数、噪声） | **能，且是差异点**；缺口只剩条件语句（世界状态读取本轮改为"声明式采样"，见 §5.6；建议再补一个选择函数） |
| 跟随 / 绑定（实体锚点、注视、避障） | **能**（注视与避障为本轮新增） |
| 事件与触发（指令、音效、特效） | **能**（Tick 轨道 + 执行器） |
| 剪辑（多镜头先后切换、过渡） | **不做**（本轮；未来视发展） |
| **多机位同时渲染 + 画面合成（分屏 / 画中画 / 遮幅）** | **能做**（本轮新增，见表 §5.5）；受帧率与着色器兼容约束，靠"可配 + 自适应降级"兜住 |
| 出片（渲染导出） | **不做**（交给 OBS / Minema 一类外部工具）；但**合成后的画面可被外部工具整体录下**，分屏成片不需要导出能力 |
| 渲染质感（景深、运动模糊、色彩） | **做不到**（MC 渲染层边界，非设计取舍） |
| 互导与协作 | **不做** |
| 数据工程质量（不可变、校验、诊断、快照、试算） | **高于同类 MC mod，接近工程化标准** |

## 5. 本轮新增六项的设计要点

六项都是"主设计未收录但已确认要做"的，写在这里以便后续并入主设计对应章节；
其中 **§5.5 多机位同时渲染改动最大**（会改数据模型的形状），§5.6 次之（会给求值上下文加一类帧事实）。

### 5.1 注视目标（look-at）

| 项 | 建议 |
| --- | --- |
| 形状 | `AimTarget(Anchor target, RotationMask mask, Vec3 offset)`：目标复用 `Anchor`（固定坐标 / 实体 / 玩家 / 第三方类型），`mask` 决定**哪几个旋转轴交给注视** |
| 归属 | 与锚点同构：**文档可带默认注视目标，播放请求可覆盖**；编辑器另有预览目标（不写文档） |
| 与旋转通道的关系 | 必须定死冲突规则：建议"`mask` 启用的轴由注视决定，其余轴由旋转通道或基础姿态补全"；这样"注视目标 + 手 K 的 Roll"可以共存 |
| 实现 | 底层 `CameraModifier.aimAt` 是**整体设置旋转**（会吃掉 Roll），所以不建议直接调它；应在本插件内用目标方向算出 Yaw/Pitch，再按 `mask` 与通道合成，最后 `setRotationYXZ` |
| 失败 | 目标不可用 → 与锚点同规则：正式播放终止并提示（D11 / §7.3）；预览显示错误、不应用该帧姿态 |
| 落点 | `api.spatial`（目标类型）+ `api.animation.playback`（请求字段）+ §6.4 合成顺序 + §7.3 失败规则 |

### 5.2 锚点位置进入表达式

| 项 | 建议 |
| --- | --- |
| 形状 | 求值上下文增加**只读空间读数**（内置量或函数）：锚点位置、注视目标位置、两者距离。命名要区分**锚点局部坐标**与**世界坐标**两套，避免歧义 |
| **不变量冲突（必须先解决）** | I7 现为"锚点不改变文档空间求值结果"。一旦公式能读锚点，这条不再成立。建议改写为 **I7′**："不读取空间读数的公式，其结果与锚点无关；读取了空间读数的公式显式依赖锚点——这是作者的选择，缓存与试算规则随之改变" |
| 缓存 | §3.4 的采样缓存键要**加入锚点帧身份**（快照身份 + 求值上下文 + 帧序号 + 曲线 ID 之外再加一项）；预览锚点一变必须重算 |
| 试算 | §4.3 的 `Incomplete` 机制正好用上：未给定锚点（或给了锚点但目标不可解析）时，含空间读数的公式只能报 `Incomplete`，不能当作通过 |
| 预览 | 编辑器预览锚点改变 → 曲线图、数值列、视口必须同时重算（本来就是同一候选快照，符合 §5.2） |
| 用途举例 | "距离越近 FOV 越小"、"边绕边看"、"锚点移动越快抖动越强"——这些都是同类 MC mod 做不出的效果 |

### 5.3 参考音轨与播放同步

| 项 | 建议 |
| --- | --- |
| 数据归属 | **音频引用（路径 + 哈希）+ 偏移 + 标记进文档**（它们是创作数据，应该能随动画一起分享）；**音频文件本身不打包**（版权与体积），文件缺失时显示"缺失"但仍可编辑 |
| 标记（markers） | 借这个机会把**标记提升为文档一等概念**（`Marker(time, label, kind)`）：同时服务音频卡点、吸附源、注释、事件参考。若不做一等概念，就只能塞进扩展轨道，吸附与波形对齐都会别扭 |
| 播放同步 | 两条路线：(a) **以音频时钟为参考**（AE/Resolve 的做法），播放头跟着音频走，需要对帧时钟做漂移校正；(b) **仅视觉对齐**：显示波形 + 播放头，不发声或只做粗略同步。建议先做 (b)，(a) 作为第二阶段 |
| **技术风险（要认）** | MC 的声音系统只播放注册过的 `SoundEvent`（资源包里的 ogg）。要播放**任意本地音频文件**，宿主必须自己走 LWJGL OpenAL（`AL10`/`AL11`）加载缓冲、管理源，并接上游戏音量设置、暂停、维度切换与失焦。这是**新增的宿主能力**，不在现有设计里，成本要单独估 |
| 落点 | 编辑器的音轨面板（UI 设计 §3.1 的画布家族）+ 播放宿主（`core.playback`）+ 文档（引用与标记） |

### 5.4 相机避障开关

| 项 | 建议 |
| --- | --- |
| 形状 | `PlaybackRequest.obstacle`（播放级）+ 会话预览开关；文档可给一个默认值 |
| 实现 | 宿主调用 `CameraModifier.enableObstacle()`；避障会**改变实际姿态**，因此预览与播放必须走同一条宿主路径，否则"预览看到的"与"播出来的"会不一致（违反 I6 的精神） |
| 顺序 | 与锚点/注视同时启用时：先合成 `WorldPose`，再交避障处理；避障结果不再参与试算与文档 |
| 落点 | `api.animation.playback`（请求字段）+ `core.playback`（应用）+ §7.2 帧执行顺序 |

### 5.5 多机位同时渲染与画面合成

本轮定的语义（对应 §3.7 那三行 ➕）：

> **同一份文档内可以有多个机位；每帧为每个机位渲染一路独立的离屏画面，再按作者设定的屏幕矩形把它们合成到画面上。**
> 多路共用同一个时钟与启停；机位之间**不做剪辑、不做过渡**（同时存在 ≠ 先后切换）；
> 路数与开销**可配 + 自适应降级**。

同源参照：[Immersive Cinematics](https://modrinth.com/mod/immersivecinematics) 的覆盖层/PiP 与 FBO 预览视口
（其公开特性里还有遮幅、字幕、形变过渡、手持抖动、注视实体/坐标/结构中心、OGG/WAV 音轨——
本轮新增的注视、抖动、音轨与它同向，差别是它做触发与过渡、我们不做）。

#### 5.5.1 数据模型：从"一套相机通道"到"若干机位"

```text
CameraAnimation
  name / symbols（共享变量与函数）/ dataVersion
  文档级轨道：事件（Tick）、音轨、遮幅、叠加层
  rigs: [ CameraRig ]                 ← 新增；取代今天"文档只有一套相机通道"

CameraRig
  id: RigId（稳定 ID，D20）/ name
  channels:  位置三轴 / 路径距离 / 旋转三轴 / FOV 的通道与关键帧   ← 就是今天的通道表
  path / motionMode / distanceMode
  space / anchorOverride / aimTarget / obstacle                    ← 每机位一份
  view: { rect（归一化 x,y,w,h；可选"锚定角落 + 像素偏移"）, zOrder, resolutionScale, updateRate, enabled }
  primary: boolean                                                   ← 哪一路驱动玩家相机
```

| 要点 | 说明 |
| --- | --- |
| 布局是创作数据 | `view` 进文档（要能随动画分享、要能被撤销）；"面板宽度""时间轴缩放"这类仍是编辑器视图状态，不进文档 |
| 归一化坐标（**已定**） | 相对窗口的 0~1 矩形为默认口径（窗口/分辨率变化后布局不散架）；另给"锚定角落 + 像素偏移"作为可选项，满足像素级对齐的诉求；两者都进文档 |
| 稳定 ID 体系已够用 | D20 规定 `TrackId` 在文档作用域内唯一——机位内的轨道不必再加前缀；`KeyId`/`PathNodeId` 同理 |
| 符号表仍共享 | 一个文档一张符号表；`TrackRef`（变量读轨道）**要求轨道 ID 文档内唯一**，这样不必把 `TrackRef` 改成"机位 + 轨道"二元键（改动最小） |
| 事件 / 音轨 / 遮幅 / 叠加层保持文档级 | 它们不属于某一个机位；事件按文档轨道顺序执行（§7.4 已定） |
| 主画面机位 | `primary` 标一位；它决定玩家相机由谁驱动。**"玩家相机不被任何机位驱动"也是合法状态**（等于多路都只是画面） |

#### 5.5.2 渲染路径

| 项 | 做法 |
| --- | --- |
| 每路一个离屏目标 | 尺寸 = 屏幕矩形 × 窗口缩放 × 该路 `resolutionScale`；走 MC 自己的渲染目标与渲染事件（FrameGraph / `RenderTarget` 一类），**不直接操作 GL 状态机** |
| 每帧顺序 | 主画面正常渲染 → 其余机位逐个渲染到各自离屏目标 → 按 `zOrder` 合成到屏幕矩形 → GUI/HUD 叠加 |
| 相机状态是全局的 | 渲染每一路都要**临时替换相机位姿、渲染、恢复**（传送门类 mod 的模板区视角与回放类 mod 的渲染器就是这条路）；必须单点封装，且渲染过程中禁止触发编辑与发布 |
| 只重复渲染，不重复模拟 | 世界刻、实体刻、粒子、区块构建、声音**只跑一次**——所以 N 路看到的是**同一瞬间**，这正好是"同一时钟"的物理解释 |
| 与遮幅/叠加层共存 | 合成层序要与 UI 设计的覆盖层、遮幅、HUD 一起定死一处（建议合成器独占"世界 → 合成 → GUI"中间那一段） |

#### 5.5.3 自适应降级（本轮定：可配 + 自适应）

| 手段 | 说明 |
| --- | --- |
| 每路分辨率系数 | 副机位常用 0.5；独立配置 |
| 每路更新频率 | 允许"每 2/3 帧更新一次并复用上一帧画面"，适合监控式副机位；主画面始终每帧 |
| 路数上限 | 配置上限；超限时按优先级（`primary` > 作者排序）停用末尾几路 |
| 帧时预算 | 按帧时间自适应：连续超预算 → 依次降分辨率 → 降频率 → 停用；恢复时按相反顺序回升，避免抖动 |
| 一键单路 | 一个开关立刻回到单路（联机、录制、性能告急时常用） |
| **降级必须可见** | 哪一路被降级/停用，编辑器与 HUD 都要有明确标识（呼应 I9"错误不得伪装"：降级同理，不允许悄悄少一路） |

> **降级与失败是两件事**：降级是**性能策略**——主动、可见、可恢复（帧率回来后按相反顺序回升），画面质量让路；
> 失败是**数据/求值出错**——任一路出错即终止整场（§5.5.5），没有"降级继续播"的余地。
> 两者都不允许静默发生。

#### 5.5.4 编辑体验

- **机位布局面板**：机位列表（增删改名、`primary`、启用、层级）+ 每路的矩形数值框；
  视口里直接拖动/缩放矩形（走 UI 设计 §4.3 的指针捕获协议），并提供预设（左右分屏、画中画、四宫格）。
- **时间轴按机位分组**：每个机位一组可折叠通道（复用现有分组折叠机制）；跨机位框选与批量移动仍然成立（§4.1）。
- **会话增加 `activeRigId`**：面板在编辑哪一路由它决定；选择仍用稳定 ID（§5.3），换路不丢草稿。
- **所见即所得**：视口预览的就是合成结果，与正式播放同一条合成路径（呼应 I6 的精神）。

#### 5.5.5 与既有决定的接口

| 既有决定 | 怎么共存 |
| --- | --- |
| 不做导出 | 合成后的画面会被外部录制工具**整体**录下 → "多机位同时出片"不必改这条决定（录到的是分屏成片）。**分路素材单独抓取**是另一件事（等价于回到导出边界），本轮未选 |
| 不做多镜头剪辑/过渡 | 机位之间是**同时存在**，不涉及先后切换与混合；每个机位自己的动画仍各自独立 |
| 注视 / 锚点 / 避障 | 全部变成**每机位一份**：不同机位可以绑不同实体、看不同目标、各自开关避障 |
| 音轨 / 事件 | 保持文档级，不随路复制（否则同一段音效会被 N 路各放一次） |
| 失败规则（D11/D18） | **已定：任一路出错即终止整场播放**（与"不允许静默降级"一致：不允许成片里悄悄少一路或某路画面是错的） |
| 分路输出 / "只渲染不合成" | **已定：不做，且不预留字段。** 该开关唯一有产出的用途是"把这一路交给外部抓取"，属于导出边界；它不能省性能（只渲染不合成反而白跑一次世界渲染），也不能用于后台触发事件（事件是文档级、由 Tick 轨道驱动，与渲染无关）。每路本来就渲染到自己的离屏目标，将来要加只是"跳过合成 + 接输出" |

#### 5.5.6 技术风险（要认）

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 每路 ≈ 一次完整世界渲染 | 2 路大致帧率减半（取决于区域复杂度）；N 路线性叠加 | 自适应降级 + 分辨率系数 + 路数上限 |
| 着色器与优化 mod 兼容 | Iris/Oculus、Sodium/Embeddium、Distant Horizons 都改写渲染管线；Immersive Cinematics 明确标榜"no OpenGL pipeline intrusion"，说明这条路确实要小心 | 只走 MC 自己的渲染目标与事件，不直接改 GL 状态；检测到不兼容环境自动退回单路并提示 |
| MC 版本渲染管线变动 | 1.21.5+ 的 FrameGraph/`RenderTarget` 与旧版差异大 | 渲染适配层隔离；降级为单路时功能不受影响 |
| 显存 | N 份离屏目标（含深度附件） | 分辨率系数 + 上限 + 视图停用时及时释放 |
| 相机状态重入 | 每路都要换相机再恢复，渲染中途被编辑打断会出乱画面 | 单点封装 + 每帧一次性渲染全部路 + 渲染期禁止发布 |
| 与窗口缩放/全屏切换 | 矩形与离屏目标的尺寸都要跟着重建 | 归一化坐标 + 尺寸变化时统一重建（UI 设计 §5.2 的失效信号里加一条） |
| 多人游戏语义 | 每个客户端各自渲染自己那几路 | 文档随包/存档下发即可，无需额外同步；"每路画面给谁看"由各客户端自己的文档决定 |

#### 5.5.7 分期建议

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| R1 数据与两路 | 机位组数据模型 + Codec + `primary` 语义；`primary` + 1 路固定画中画 | 两路同一时刻、同一时钟；副机位可单独关闭；单路时行为与今天一致 |
| R2 布局与编辑 | 布局面板 + 视口拖拽 + 预设 + 时间轴按机位分组 + `activeRigId` | 作者能排出左右分屏/画中画；布局随文档保存与撤销；换路不丢草稿 |
| R3 多路与降级 | N 路 + 自适应降级 + 降级可见性 + 兼容性开关 | 帧率不达标时自动降级且界面明示；不兼容环境自动退回单路 |

> R1 之前的准备工作：现有 `ViewportPipRenderer` 是"把游戏主画面拷进纹理再贴回来"，
> 与"渲染第二个相机视角"不是一回事——多机位需要的是**再跑一次世界渲染**，
> 这条要在 R1 里先做一个最小验证（哪怕只有一路、固定矩形），确认与着色器/优化 mod 的实际兼容性再往下走。

### 5.6 声明式世界采样

本轮定的语义：

> **文档声明要读哪些世界量（采什么、在哪采），宿主每帧采集一次填进求值上下文，表达式按名字读。**
> 不是"任意查询函数"：作者不能在中途随意问世界，只能读**已声明、已采集**的样本。

#### 5.6.1 为什么不做成查询函数

| 任意查询函数（`block(x,y,z)` 直接查世界）的问题 | 声明式采样的对应做法 |
| --- | --- |
| 求值不再是纯函数：同一时刻两次求值可能不同 | 一帧采集一次，帧内所有通道读**同一张表** |
| 预算不可控（一个公式可以循环里查上千次） | 样本数量与采集次数**在提交期就有上界**（L4 可校验） |
| 可能顺带触发区块加载（灾难） | 只读**已加载**数据，绝不触发加载；取不到就是 `UNKNOWN` |
| 试算（§4.3）直接失效 | 试算用"编辑器当前时刻的一份采样"填充；取不到则报 `Incomplete` |
| 多人下各客户端结果不同且无法解释 | 默认**本地采样**并在文档里写明；需要一致时由服务端下发采样表（§5.6.5） |
| 缓存键无法定义 | 缓存键加"采样表版本"（§3.4 那一行加一项） |

一句话：**把"世界读数"做成宿主灌进求值环境的帧事实，就像 `worldTime` 一样，只是从标量变成一张表。**

#### 5.6.2 数据形状

```text
CameraAnimation
  samples: [ WorldSample ]              ← 新增；文档级（世界对所有机位是同一个）

WorldSample
  id: SampleId（稳定 ID，D20 家族）
  name: String                          ← 表达式里用的名字；文档内唯一
  kind: Identifier                      ← 采样类型，注册表分派（见 5.6.8）
  args: <由类型自己的 MapCodec 定义>     ← 坐标 / UUID / 记分板目标名 …
  resampleEveryTicks: int               ← 重采周期（默认每次采集；静态量可设大）
```

- **文档级而不是每机位一份**：世界是共享的；多机位读同一张表。
- **表达式访问用内置函数 `sample("名字")`**，不占用变量/函数/内置量（`t`/`p`/`wt`）的命名空间；
  名字打错在提交期就能报（L3 校验：引用的样本必须已声明）。
- **一律返回 float。** 表达式只有数值：分类量以**匹配查询**的形式提供，例如
  `sample("ground_is_stone")` 返回 0/1，而不是返回"方块 id 的哈希"（哈希不可读也不可移植）。

#### 5.6.3 采样类型（最小集）

| 类型 | 参数 | 读数 | 备注 |
| --- | --- | --- | --- |
| 方块匹配 | 坐标 + 方块 id / 标签 | 0/1 | 需要区块已加载 |
| 群系匹配 | 坐标 + 群系 id / 标签 | 0/1 | 同上 |
| 光照 | 坐标 | 天空光 / 方块光（0~15） | 读取成本低 |
| 天气与月相 | 无 | 晴/雨/雷、月相 | `wt`（世界时间）已有，这两项补齐 |
| 记分板 | 目标名 + 持有者 | 分值 | 服务端权威；客户端未同步 → `UNKNOWN` |
| 实体属性 | 锚点引用（UUID/选择结果）+ 属性名 | 血量、是否潜行、是否骑乘、姿态、速度… | 复用锚点的解析机制 |
| 玩家属性 | 玩家 UUID + 属性名 | 同上 | |

#### 5.6.4 采集、缓存与失败

- **采集时机**：每帧的**准备阶段**（§7.2）一次性采集，执行阶段只读表——与"一帧只捕获一次快照"同源。
- **预算**：单帧样本数上限、坐标类采样去重（同坐标同类只采一次）、`resampleEveryTicks` 降低静态量的开销。
- **缓存键**：§3.4 的采样缓存加"采样表版本"；`resampleEveryTicks > 1` 时版本不必每帧变。
- **`UNKNOWN` 的处理**（建议口径）：
  - `sample("名字")` 取不到 → 该通道 `ERROR` → 正式播放终止（D18），诊断**指名是哪个样本、为什么**（坐标未加载 / 实体不存在 / 记分板目标不存在）。
  - 同时提供**显式**双参形式 `sample("名字", fallback)`：缺省值是**作者写出来的**，不是系统静默降级；
    这样"站在未加载区块边上就停播"有出口，但出口在公式里看得见。
  - 编辑器里把 `UNKNOWN` 样本与依赖它的通道标红（I9 精神）。
- **试算**：用编辑器当前世界采一份填进去；仍取不到的样本 → 报 `Incomplete`，不阻断提交（§4.3）。

#### 5.6.5 预览与多人

| 场景 | 口径 |
| --- | --- |
| 编辑器预览 | 读**编辑器当前世界**的采样值；曲线图/数值列随之刷新（与 §5.2 锚点读数同一套刷新规则）。编辑器要明示"这一项依赖世界状态"，避免作者以为预览=成片 |
| 单人正式播放 | 读本地世界，行为与预览一致 |
| 多人正式播放（默认） | **每个客户端读自己看到的世界** → 各人画面可能不同。这是默认语义，必须写进文档与指南 |
| 多人正式播放（可选） | 需要"全场一致"时，由服务端在播放请求里**附带一份采样表**（§8.3 网络包加一个可选字段），客户端优先用它。服务端权威场景因此也能做一致 |

#### 5.6.6 编辑器与扩展

- **世界采样面板**：声明 / 命名 / 参数 / **实时显示当前值**（`UNKNOWN` 显示原因）/ 点一下把 `sample("…")` 插进公式（与变量表同一套交互）。
- 采样列表是**文档数据**：可撤销、随动画分享、走同一套校验与 Codec。
- **采样类型注册表**（D16 由"两项"扩为"三项"：轨道、锚点、**采样**）：
  第三方可注册自己的读数（魔法值、任务进度、自定义实体状态）。
  结构与锚点类型注册表同构：**id + `MapCodec` 双端可用，采集器只在客户端**。

#### 5.6.7 风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 客户端缺数据 | 未加载区块、未同步实体、未同步记分板 → 长期 `UNKNOWN` | 诊断写明原因；`sample(name, fallback)` 显式兜底；编辑器面板实时显示 |
| 试算覆盖不到 | 采样值在试算时只是"当前世界的一份" | `Incomplete`；面板与文档明示"依赖世界状态" |
| 多人不一致 | 各客户端看到的世界不同 | 默认本地采样并写明语义；需要一致时服务端附带采样表 |
| 性能 | 大量坐标采样 | 单帧预算 + 去重 + 重采周期 |
| 与"不静默降级"的一致性 | 世界读数天然可能取不到 | 只用**显式**兜底；缺省绝不做隐式处理 |
| 观感 | 相机能读到其他实体/玩家的数据 | 只读客户端本来就可见的数据，不新增越权能力 |

#### 5.6.8 分期

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| S1 | 采样声明 + 求值上下文/缓存键 + 最小类型（方块匹配、光照、实体属性）+ 诊断 | 采样在帧内一致；取不到时终止并指名样本；试算报 `Incomplete` |
| S2 | 记分板、群系、天气月相 + 编辑器面板（实时值 + 插入公式） | 作者能在公式里用采样值；`UNKNOWN` 在面板与曲线图上可见 |
| S3 | 服务端附带采样表（多人一致）+ 重采周期与预算调优 | 服务端权威场景下各客户端结果一致 |

### 9.3 §5 六项方案的技术纠正

1. **注视**：当前实际依赖的 aimAt 只修改 Pitch/Yaw，保留 Roll，原 §5.1“吃掉 Roll”不正确。仍由纯姿态求解支持掩码与退化方向，内部弧度到基础 API 度在宿主边界转换。
2. **空间读数**：不仅修改 I7，还须处理共享符号的机位上下文、跨机位 TrackRef、冻结事实与缓存身份；锚点速度不能凭位置接口自动获得。
3. **音轨**：宿主声音系统存在 SoundInstance/声道/音频流抽象，不能断言必须直接用 AL10/AL11。任意本地资源、定位、变速与漂移仍需能力验证；先视觉后有声。
4. **避障**：当前 enableObstacle 以玩家眼睛为起点做遮挡收缩，不能直接覆盖每机位语义。需采用本次确认的起点规则，独立宿主适配，不承诺运动碰撞模拟。
5. **多机位**：MC 26.1.2 按视角提取再渲染，需要独立相机/可见性/投影/提交状态；主纹理 PiP 不代表第二视角。模拟一次不等于所有视角工作一次；隔帧更新允许旧帧，必须标识采样时刻。使用原版抽象不保证着色器/优化模组兼容，远机位也受客户端区块加载范围约束。
6. **世界采样**：现有语法无字符串 AST，内置函数急切求值；sample 静态名字绑定、惰性 fallback/select 需要编译器和求值器配套。resampleEveryTicks 明确按游戏刻；每帧冻结可用表而非每渲染帧重复重采。一次服务端附表不能保证动态世界一致，本轮移除 S3 同步承诺。

### 9.6 后续确认：统一关键帧与注视交还

注视、机位活动和相机来源直接采用正式时间轴有类型关键帧轨道，复用 TrackId/KeyId、选择、移动、吸附、复制、校验、Codec、原子提交与历史；STEP 仅是这些轨道的插值限制，不单独建设 StepProperty 系统。注视的 Off/Target、活动布尔及来源 Player/Rig 使用原生类型，不能编码为数值曲线或向数值 KeyField 强塞对象。

前 1 秒注视、后 1 秒按旋转轨道：注视 0 秒 Target(A)、1 秒 Off；旋转 1 秒 R₁、2 秒 R₂。恰好 1 秒起停止覆盖 Yaw/Pitch，采用该时刻旋转通道，Roll 按原规则处理；Off 不恢复上次姿态，无自动平滑。

显式“将注视姿态转为旋转键并关闭注视”工具按冻结的 t 时刻世界事实求关闭前姿态（已有 Off 时可用左侧目标配置），转回机位参考系，一次写 XYZ 常量旋转键与 Off。替换同时间键/公式须确认，固定 Target 覆盖需先清除；缺事实/退化/过期一律整批拒绝，一次撤销恢复。只保证捕获事实下的边界匹配，移动目标重播不保证连续。

规范与验收落点：主设计 §3.1.1、§4.7、§6.4、§10.1；UI §3.3、§6.5、§10；P1 契约计划 §1.4、§7.4。此处不宣称已经实现，也不额外承诺动态混合或上一帧姿态继承。
